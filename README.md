# 出图

一款本地优先的桌面 AI 图片创作工具，支持多画布、文生图、图生图、图片编辑和版本管理。

> 这个仓库已经准备好用于 Vibe Coding。开始开发前，请先运行项目，再阅读需求文档并对照真实 UI 设计稿，不要只根据文字重新想象界面。

## 当前已经实现

### 多画布

- 创建多个画布并录入名称。
- 点击画布卡片直接打开，并展开或收起图片元素列表。
- 画布卡片展示首张作品封面、作品数量和更新时间。
- 右键画布可以修改名称、新建 AI 图片或上传图片。

### 画布交互

- 无限平移和缩放。
- 选择工具、抓手工具、框选和多选。
- 图片节点自由拖动并持久化坐标。
- 适配全部内容和适配选中内容。
- 点击左侧图片元素后，在画布中选中并居中对应图片。

### 图片管理

- 上传本地图片到指定画布。
- 图片右键菜单支持编辑和删除。
- 删除前显示确认弹窗，并同时删除关联历史版本。
- 将图片以 PNG、JPEG 或 WebP 保存到本地。

### AI 图片生成

- 文生图和图生图使用两套独立模型配置。
- 内置 OpenAI 官方服务预设，也支持 Constreet 和自定义 OpenAI 兼容服务。
- 选择 OpenAI 官方后自动填入接口地址，模型 ID 支持建议列表和手动输入。
- OpenAI 官方服务支持可选的 HTTP、HTTPS、SOCKS5 网络代理；连接测试、图片生成、图片编辑及结果下载共用对应模型的代理配置。
- 支持正方形、横图和竖图尺寸。
- 支持 `low`、`medium`、`high` 三档质量。
- 模型配置支持连接测试，可检查 API Key、网络和目标模型。

### 图片编辑与版本

- 亮度、对比度和饱和度实时调整。
- 左转、右转、水平翻转和垂直翻转。
- 原始图片自动保存为 V1。
- 每次图生图生成一个递增的新版本。
- 可以在版本列表中预览、选择和应用历史版本。
- 按图片原始分辨率导出调整结果。

### 本地持久化

- 画布、图片、提示词、坐标、版本和模型配置保存在本地。
- 使用 SQLite 数据库，不依赖远程业务服务器。
- Electron 渲染进程不直接访问 Node.js、数据库或本地文件系统。
- API 请求和文件保存统一由 Electron 主进程处理。

## 快速运行

环境要求：

- Node.js 20 或更高版本。
- npm 10 或更高版本。
- macOS 或 Windows 桌面环境。

安装依赖并启动开发模式：

```bash
npm install
npm run dev
```

执行生产构建校验：

```bash
npm run build
```

预览生产构建：

```bash
npm run preview
```

## 第一次使用

1. 启动应用。
2. 点击右上角“模型配置”。
3. 分别配置文生图模型和图片编辑模型。
   - 使用官方服务时，服务类型选择“OpenAI 官方”，填写自己的 OpenAI API Key；接口地址自动填入，模型 ID 可按账户权限修改。
   - 默认使用 `gpt-image-2.6-flare`，支持的模型与参数可查看 [OpenAI 图片生成文档](https://developers.openai.com/api/docs/guides/image-generation)。
   - 如需网络代理，在对应模型下勾选“使用代理”，填写完整地址，例如 `http://127.0.0.1:7890` 或 `socks5://127.0.0.1:1080`。代理程序需要已启动，当前支持无需用户名和密码的代理。关闭后直连，文生图和图生图分别保存设置。
4. 使用“连接测试”检查 API 地址、API Key 和模型名称。
5. 新建画布。
6. 通过画布右键菜单生成或上传第一张图片。

没有配置模型时，上传图片、画布和本地基础编辑仍然可以使用。

## 用本机 Agent 操作画布

1. 打开桌面应用，点击顶部 **MCP → 启动服务**。服务地址为 `http://127.0.0.1:38473/mcp`。
2. 使用 Codex 时，点击 **复制 Codex 配置**，粘贴到用户级 `~/.codex/config.toml`，重新加载 Codex。其他支持 Streamable HTTP 的客户端可使用上面的地址，并在 `Authorization` 请求头填入 `Bearer <MCP 访问令牌>`。
3. 试着对 Agent 说「列出出图里的画布」，或者「在『夏季新品』画布生成一张 3:2 的商品海报」。

- 用 `list_canvases` 查画布，用 `create_canvas` 新建，用 `rename_canvas` 重命名。
- 用 `list_artwork_groups` 查看画布内分组，再按任务用 `create_artwork_group` 自定名称。用 `rename_artwork_group` 重命名，`reorder_artwork_groups` 按提交的全部分组 ID 排序。用 `assign_artworks_to_group` 批量归组，`groupId: null` 移回未分组。`delete_artwork_group` 删除分组，组内图片回到未分组。
- 用 `import_local_image` 传入 `canvasId` 和 `filePath`，将本机图片导入指定画布。路径须为运行出图的电脑上的绝对路径，支持不超过 20 MB 的 PNG、JPEG 和 WebP。工具返回 `artworkId`、文件名及图片尺寸。
- 用 `list_artworks` 查画布里的图片，可按 `groupId` 筛选。用 `move_artwork` 设置图片左上角的画布坐标 `x` 和 `y`，支持负坐标。
- 用 `delete_artwork` 或 `delete_canvas` 永久删除。两项工具都需要 `confirm: true`，会删除对应图片的历史版本和分层海报。删除画布会一并删除其中的所有图片。
- 用 `generate_image` 按应用保存的文生图模型和代理生成一张图片，再用 `get_image_job` 查询结果。生成成功后，图片会自动显示在目标画布。重试同一次提交时复用 `requestId`，可以避免重复生成。

MCP 仅供本机使用，需保持应用运行。服务开关和访问令牌会在下次启动时恢复，任务状态仅在当前进程保留。停止 MCP 服务后，已提交的任务仍会继续执行。请把复制的访问令牌保存在客户端的本地配置中。

## 画布内分组

打开「画布操作」菜单，点击「新建分组」并填写名称。在侧栏把图片拖到组名上，或在画布中选择一张或多张图片，再点击顶部的「分组」。点击组名可在画布中定位相应图片。分组菜单提供重命名、上移、下移和删除。

## 图片编辑器

双击画布里的图片进入编辑器。在左侧切换调整、裁剪、调色、精修、磨皮或图生图，中间查看效果，右侧打开「属性」「图层」「版本」或「历史」。窄窗口会将工具栏和属性面板排在图片上下。

打开「图层 → 添加图片」可从当前画布一次选入多张图片。拖动列表右侧的手柄调整图片、主体和文字的叠放顺序。选中图片后，拖动图片可移动，拖动四角可等比缩放，拖动四边的手柄可单向拉伸，拖动圆形旋转手柄可转动图片。也可以在属性面板输入位置、大小、角度并调整不透明度。背景位于底层，接触阴影随主体移动。

单图「调整」和海报「图层合成」的工具栏都有「图像尺寸」与「画布尺寸」。前者缩放图片内容或海报排版，可锁定宽高比。后者按九宫格锚点扩展或裁切边缘，保持已有内容的大小。单图调整另存为版本，海报尺寸直接保存在文档中。

主体的纯色背景可通过边缘颜色去除，复杂背景可沿主体边缘手动描边。每张图片的图层文档首次创建时绑定选中的图片版本。新增图片图层绑定添加时的素材版本。修改会自动保存。

选中主体、图片图层或图片背景，点「添加蒙版」后用「隐藏」和「恢复」画笔修边。可开启「显示蒙版叠加」查看隐藏区域。用「绘制选区」框出要保留的范围，再点「选区转蒙版」。精修和调色中的选区也可以用于同一图片版本的图层。已有的纯色抠图和手动描边蒙版都可以继续修边。

选中图片图层后点「像素编辑」。画笔可调颜色、大小和不透明度，橡皮擦将涂过的像素擦成透明。仿制图章可先点「选择取样点」，也可以按住 Option 或 Alt 选点，随后连续涂抹。每笔修改自动保存到当前图层，并进入统一历史。

在像素编辑中点「移除物体」或「局部重绘」，框选要改动的区域，生成预览后点「应用结果」。物体移除在本机用周围像素填补，适合简单背景。局部重绘使用已配置的图生图模型，应用时只合入选区内的结果。

顶部可逐步撤销和重做，右侧「历史」可直接点选任一步。图层修改、每笔蒙版、尺寸调整、另存的裁剪或调色版本及应用到画布按提交顺序记录，每张图片保留最近 60 个状态。回到旧步骤后继续编辑，会清除后续重做记录，已经保存的图片版本仍可在「版本」中查看。

Agent 可用 `get_artwork_preview` 看原图，用 `open_poster` 创建或打开文档，按返回的 `revision` 通过 `edit_poster` 修改图层。用 `get_editor_history` 查看历史，用 `navigate_editor_history` 跳到任一步。用 `preview_poster` 检查排版，用 `export_poster` 导出。支持 PNG 和 JPEG，可导出当前尺寸、1080 × 1080 方图或 1080 × 1620 竖图，文件保存到本机下载目录中的「AI设计助手」。

用 `inspect_poster_layer_pixels` 查看当前图层，用 `preview_poster_layer_mask` 查看图层与蒙版。用 `paint_poster_layer_pixels` 提交一笔画笔、橡皮擦或连续仿制图章。图层点位使用 0–1 坐标，每笔都记录到统一历史。

用 `preview_poster_layer_region` 预览选区内的物体移除或重绘。移除直接返回预览和 `draftId`。重绘先用 `list_image_edit_models` 取模型 ID，提交后按 `jobId` 用 `get_poster_region_job` 取预览。确认后用 `save_poster_layer_region` 应用，重试同一次重绘提交时可复用 `requestId`。

可以对 Agent 说「用画布上的商品图做一张海报。抠掉白底，换成暖灰背景，加接触阴影，标题写『夏日限定』，价格写『¥ 99』，先预览，再导出方图和竖图。」

## 用 Agent 精修人像

图片编辑器提供「人像磨皮」，支持调整磨皮、提亮强度和处理范围。也可以请 Codex 先看预览，按肤质、光线和用户要求决定强度，再调用 `retouch_portrait`。合照可以处理所有人脸、主要人脸，或框选要处理的人脸。

- `underEyeShadows` 轻抬眼下阴影，`cheekTone` 均匀两颊的局部色差。两项强度均为 0–100，可独立使用。
- `dressHighlights` 压低白纱亮部。填写 `strength`（1–100），并在 `region` 中沿白纱传入原图归一化的多边形顶点 `[{ x, y }, …]`。
- 用 `versionId` 指定精修的源版本。可把三项精修与 `smoothing`、`brighten` 一起提交。MCP 中省略 `smoothing` 时，磨皮强度为 0。

精修和人脸定位在本机执行，结果保存为新版本。Agent 可用 `get_artwork_preview` 传入版本 ID 检查结果，确认后用 `apply_artwork_version` 应用到画布。让 Codex 看图时，预览缩略图会通过 MCP 返回给 Codex。

人脸定位使用 [OpenCV Zoo 的 YuNet 模型](https://github.com/opencv/opencv_zoo/tree/47534e27c9851bb1128ccc0102f1145e27f23f98/models/face_detection_yunet)，MIT 许可证随模型保存在 `electron/assets/yunet`。

## 局部精修

在图片编辑器点「局部精修」，可以框选放大、用矩形、椭圆、描边或画笔加选和保护区域，再添加调色、点修、取样克隆或纹理操作。点「预览对比」查看同位置的前后效果，满意后另存为新版本。切换画布上的图片通过编辑器的「应用到画布」完成。

在 Codex 里可以直接说「看下当前这张，眼下的阴影提一点，先给我看看对比」。

1. `get_editor_context` 返回当前画布、选图和正在查看的版本；按名称查找可用 `list_canvases` 和 `list_artworks`。
2. `inspect_artwork` 读取全图或局部裁切。`region` 的 `x`、`y`、`width`、`height` 相对于整张源图，取值 0–1；元数据也记录原图尺寸和裁切像素位置。
3. `preview_photo_mask` 读取加选、保护和羽化后的叠加预览。调色或纹理操作可直接携带同样的 `mask`，省略即调整全图。点修可自动取样，克隆需要指定取样位置。
4. `preview_photo_edit` 按顺序渲染一组操作，返回同范围的前后图和临时 `draftId`。预览阶段不写入版本库。支持再次生成对比来调整方案。
5. `save_photo_edit_version` 把草稿另存为全分辨率版本，`apply_artwork_version` 再将指定版本显示到画布。预览草稿在当前进程中保留 20 分钟，最多保留近期 32 份。

## 调色

打开「图片编辑器 → 调色」，可以在底图上取样、查看 RGB 直方图、调整白平衡和曝光、编辑 RGB 或单通道曲线、分颜色调 HSL、给不同亮度范围上色。用「保护区域」圈出白纱或肤色，可以保护这些区域。点击「预览对比」查看效果，确认后可另存版本。

- `inspect_photo_colors` 读取直方图及局部色样。`preview_photo_edit` 接受 `grade` 操作，可以和其他修图操作串联。`mask.include` 为 `[]` 时，`exclude` 从全图减去相应区域。
- 另存调色版本时会保留底图和参数。应用中选中该版本再次点「调色」会加载配方，MCP 可用 `get_photo_edit_recipe` 读取后改参数重新预览。

## 黄金构图裁剪

打开「图片编辑器 → 裁剪」，选画幅比例或自由裁剪。拖动框内移动裁剪框，拖角调整大小，可以切换 38.2%／61.8% 黄金网格。选定比例后点选主体，再点「推荐裁法」比较候选。点「预览裁剪」查看原图构图框和裁剪结果，再按需另存版本或应用到画布。

点「拉直」，沿地平线或其他水平边缘拖出参考线。也可以用角度滑杆或数值微调。裁剪框会收在旋转后的图像范围内，避开露出的空边。

1. MCP 用 `inspect_artwork` 查看指定源版本，定位构图重点。
2. 用 `suggest_artwork_crop` 传入 `aspect`，可选 `focus`、必须完整保留的矩形 `keep`，以及水平线位置 `horizon`。这三项使用相对源图的 0–1 坐标。返回候选的像素框、保留比例和效果图。
3. 把选中的像素框传给 `preview_photo_edit` 的 `{ "type": "crop", "box": … }`，裁剪须在操作列表末尾。预览生成后可用 `save_photo_edit_version` 另存全分辨率裁剪版本，再用 `apply_artwork_version` 切换画布版本。

## 推荐的 Vibe Coding 流程

1. 阅读 [需求文档](./docs/需求文档.md) 中对应模块的功能和验收标准。
2. 打开 [UI 设计稿目录](./docs/design/)，确认目标状态真实长什么样。
3. 执行 `npm run dev`，亲自操作当前功能，理解现有交互。
4. 使用 `rg` 找到对应组件和主进程接口，尽量复用现有结构。
5. 完成一个小闭环后立即在运行中的 Electron 应用内验证。
6. 执行 `npm run build`，保证 TypeScript 和三个构建目标全部通过。
7. 涉及 UI 的修改，在 `1440 × 920` 窗口下对照设计稿检查。

## Vibe Coding 约束

- 不要把画布改成普通图片网格或瀑布流。
- 不要制作只有视觉、没有实际行为的静态按钮和菜单。
- 保持顶部栏、320 px 左侧栏和右侧画布的主要结构。
- 保持灰白色界面和紫色选中反馈，不随意引入新的主色。
- 新建、生成、保存和删除操作必须有加载、成功或错误反馈。
- 删除等破坏性操作必须二次确认。
- 画布平移、缩放、选择、拖动和居中定位必须真实可用。
- 修改数据持久化逻辑时必须兼容已有本地数据。
- 不要在渲染进程中直接访问 API Key、文件系统或数据库。
- 需求文档与真实运行行为冲突时，先确认产品意图再大范围重构。

## 开发完成标准

提交代码前至少完成：

- 对应功能能够从 UI 入口完整操作成功。
- 取消操作不会产生数据变化。
- 失败状态有明确提示，不会伪装成成功。
- 重启应用后，已经保存的画布、图片、位置和版本仍然存在。
- `npm run build` 通过。
- 控制台没有由本次修改引入的持续错误。
- UI 修改与 `docs/design` 中的真实运行基线保持一致。

更完整的逐项验收标准请查看 [需求文档](./docs/需求文档.md#11-验收标准)。

## 本地数据位置
